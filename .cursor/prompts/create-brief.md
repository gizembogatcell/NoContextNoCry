Create a project brief at `docs/brief.md` for this hackathon project.

## Instructions

1. Read `docs/brainstorm-notes.md` if it exists. If not, ask the user to describe the project concept in a few sentences.

2. Ask the following questions one at a time, waiting for each answer before asking the next:
   - "What is the core problem being solved? (one sentence)"
   - "Who is the primary user?"
   - "What are the 3–5 must-have features for the hackathon MVP?"
   - "What are the main constraints? (time, team size, tech preferences)"

3. Generate `docs/brief.md` with this exact structure:

```markdown
# Project Brief: {Project Name}

## Problem Statement

{One clear paragraph: what problem exists, who has it, why it matters}

## Proposed Solution

{What we are building and why it will work}

## Target Users

**Primary**: {Who, specific description}
**Secondary**: {Who else might use this, if applicable}

## MVP Features (Hackathon Scope)

1. {Feature} — {why it's essential}
2. {Feature} — {why it's essential}
3. {Feature} — {why it's essential}

## Out of Scope (for hackathon)

- {Thing we are not building}
- {Thing we are deferring}

## Success Criteria

- {What does "done" look like for demo day?}
- {Key metric or demo outcome}

## Constraints

- **Time**: {hackathon duration}
- **Team**: {team size, roles}
- **Tech**: {any preferences or restrictions}
```

4. Review each section with the user before saving.
5. Save to `docs/brief.md` and confirm the path.
